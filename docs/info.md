## 5. What You Must Submit (Submission Requirements)

Every submission on Devpost must include ALL of the following:

1. **Project (the working software).** A working Agent Skill, MCP server, app, or feature that meets the requirements of the chosen primary track (Section 6).
2. **Text description** explaining the project's features and functionality, plus a clear statement of how it uses the track's required technology.
3. **Code repository on GitHub** (GitHub specifically; other hosts are not accepted) containing all source code, assets, and instructions needed to run the project. Either:
   - **Public** with an open-source license file in the repo, or
   - **Private**, shared before the deadline with `testing@devpost.com` and the Amazon GitHub accounts `chris-trag`, `knmeiss`, `giolaq`, `anishamalde`, `mosesroth`, `emersonsklar`.
4. **Runtime proof of the track technology.** "The repository must demonstrate use of your track's required technology at runtime in your code — imported and actually called (a library import, an app/backend entry point, or a loaded agent/flow/MCP config), not just named in the README." (Alexa+ simulated experiences are exempt but must include the simulation source.)
5. **Demo video**, under 3 minutes, uploaded to YouTube or Vimeo and publicly visible, showing the project functioning on the device (or simulator) it was built for. No third-party trademarks or copyrighted music/material without permission. Judges are not required to watch beyond 3 minutes. English (or with English translation).
6. **Product feedback** for every developer tool, API, or SDK used: which tools/APIs/SDKs were used and for what; what worked well; what needs work; how the onboarding experience was; whether you would build with these devices and services again.
7. **Track selection**: the primary track (Fire TV, Alexa+, Bee, or Ring) and any mini challenges (AWS Builder, Open Source).
8. **Pre-existing project explanation** if the project existed before 31 Aug 2026: clearly describe and demonstrate the feature updates made during the submission period.
9. **Optional: friction log entries** (earn up to a 10% bonus). Each entry: specific task attempted, steps taken, expected vs actual result, severity rating, workaround used, actionable suggestion.
10. **Optional: feature requests** (also count toward the friction log bonus).
11. **Testing instructions** including any login credentials if the project is behind authentication, and hardware notes if proprietary hardware is involved (Sponsor may request physical access to proprietary hardware).
12. All materials must be in English or accompanied by an English translation.

Sources: https://amazonappdev2026.devpost.com/rules , https://amazonappdev2026.devpost.com/details/faqs

## 6. Primary Tracks (Exact Requirements)

### 6.1 Fire TV

- **Requirement:** "Launch a demo-ready app on Fire OS or Vega OS. Use React Native, web technologies, or Android (Kotlin/Java)." The demo video must show the app running on a Fire TV device or a simulator (Vega Virtual Device or Android emulator/Fire OS device).
- **Priority categories:** AI-enhanced viewing, sports, fitness, family entertainment, multi-modal UX, computer vision.
- **Organizer hints (Devpost update, 18 Sep):** go beyond a basic video player; examples given were "a computer vision fitness app using the TV's camera" and "a multi modal experience blending voice, D-pad, and visuals."
- **Hardware:** not required; simulators are sufficient.
- **Reference stack Amazon promotes:** React Native for Vega (the `react-native-multi-tv-app-sample` is called "the most complete starter"), Kotlin + Jetpack Compose for Fire OS, or web apps in the Vega/Fire OS WebView. Amazon Devices Builder Tools (MCP server + Agent Skills) for AI-assisted development.
- **Recent platform news:** Alexa+ is free on all US Fire TVs (Aug 2026); OpenIAP now supports Fire OS and Vega OS; Fire TV Beta program lets developers test against pre-release Fire OS builds; AI-assisted Fire OS to Vega migration guide published.

### 6.2 Alexa+

- **Requirement:** "Build a working Agent Skill or a self-hosted MCP server, implementing MCP spec version (minimum acceptable version is 2025-11-25)" using Streamable HTTP transport. "MCP is the open standard that powers Alexa+ integrations."
- **Runtime requirement:** the skill/server must be imported and actually called in code (not just described).
- **Alternative path:** "developers can simulate the Alexa+ experience in a web app using their own agentic tools." This path is exempt from the runtime hook requirement, but the code must include the simulation source and the demo must show the simulated experience.
- **Important limitation (FAQ):** Amazon's gated Alexa+ Add-on developer tools (Category SDK, MCP Toolkit, CLI, Web Simulator) are in preview for select partners only and are **not** available to hackathon participants. Everyone in this track is therefore building a self-hosted MCP server / Agent Skill and demonstrating it with their own client or simulator (MCP Inspector, Claude, Kiro, a custom web voice UI, etc.).
- **What counts as a significant update (FAQ):** "A new conversational feature that brings new functionality to an existing app can count as a significant update." A locally runnable public repo plus a demo video is sufficient; deployment is not mandatory.
- **Hardware:** none required.
- **Context:** Alexa+ is live in 12 countries (US, Italy, Mexico, Canada, UK, Spain, Austria, Germany, France, Brazil, Australia, India as of Sep 2026). Alexa+ Add-ons now support in-conversation payments (UCP-compatible checkout, partner as merchant of record).

### 6.3 Bee (Wearable AI)

- **Requirement:** "The project must be connected to data recorded and processed through an actual Bee device or an Apple Watch running the Bee software. The demo video and code must show the project actually using that Bee data to do something for a customer." No public-facing integration is required.
- **Priority use cases:** education, developer experience, personal productivity.
- **Hardware reality:** requires a Bee account with real data. Per FAQ, "You need to pair a Bee device before Developer Mode becomes available in the Bee app's Settings." (Bee sells a dedicated wearable; the Bee app also runs on Apple Watch.)
- **Tooling:** Bee CLI (`npm install -g @beeai/cli`, `bee login`), Bee MCP server, Bee Skill for agents, REST API via Developer Mode. Docs: https://docs.bee.computer/

### 6.4 Ring

- **Requirement:** "A working app or new feature that utilizes Ring APIs, SDKs, simulators, or devices, demonstrated through a simulator or an actual device."
- **Priority categories:** access control, business systems, IoT home automation, accessibility, caretaking.
- **Hardware:** "No physical device required." The Ring Developer Playground (released 28 May 2026) issues 30-minute OAuth tokens without app registration, account linking, or a Ring subscription, exposes an interactive API explorer, and includes **live view event simulation for Package, Vehicle, and Motion event types with a full WebRTC/WHEP session workflow**. Staging users no longer need to purchase a subscription to test a staging app (11 Sep 2026).
- **Platform facts:** Ring Partner API (base `https://api.amazonvision.com`, JSON:API), OAuth 2.0 with one-way account linking, webhooks with HMAC-SHA256 signatures, WHEP/WebRTC and RTSP live video, snapshot and clip download (with mandatory watermark since June 2026), chime audio playback, sensors (early access), dynamic scopes (early access), Ring Appstore MCP server for AI-assisted coding, `ring-api-helloworld` reference app (Next.js 14 + Tailwind + WebRTC + SSE).
- **Business context:** Ring Appstore launched in spring 2026 (US first) with launch partners across elder care (Density Routines), business analytics (QueueFlow, Lumeo, StoreTraffic, ProxView), rental management (Minut), pets (Meld), pools (PoolScout, Maytronics), packages (Package Protect), and Toast's Cheer Chime. Ring takes a 10% revenue share; publishing is free; facial recognition and license plate reading apps are prohibited.

Sources: https://amazonappdev2026.devpost.com/rules , https://amazonappdev2026.devpost.com/details/faqs , https://developer.amazon.com/docs/ring/release-notes.html , https://techcrunch.com/2026/03/31/ring-app-store-bets-on-ai-to-go-beyond-home-security/ , https://dev.to/amazonappdev

## 8. Judging

### 8.1 Two-stage process

**Stage One (pass/fail viability check).** Each submission is checked to confirm "the Project reasonably fits the theme and reasonably applies the required APIs/SDKs" of its selected track, plus that all required materials are present. Submissions that fail are eliminated.

**Stage Two (panel scoring).** Submissions that pass are scored by the judging panel on four **equally weighted** criteria:

| # | Criterion | Exact wording | What the panel is really asking |
|---|---|---|---|
| 1 | Tech Implementation | "How well is the project built, and how effectively does it use the required tech?" | Is the code real, runnable, robust, and does it use the track's APIs/SDKs deeply rather than superficially? |
| 2 | Design | "Does the project deliver a complete, coherent product experience?" | Is there an intuitive interaction model, a finished UI, and an end-to-end flow (not a demo of one endpoint)? |
| 3 | Potential Impact | "Does the project make a credible case for solving customer needs?" | Is there a realistic audience beyond the hackathon (rules cite the Fire TV Appstore and Ring Appstore as distribution paths)? |
| 4 | Quality of the Idea | "Is this a creative, imaginative use of the required tools?" | Does it show genuine understanding of the ecosystem and end users, rather than a generic wrapper? |

**Bonus:** up to 10% added to the final score based on Amazon's internal review of friction logs and feature requests (passed to the Stage Two panel).

**Tie-breaking:** highest score on criterion 1; if tied, criterion 2; then 3; then 4; if still tied, judges vote.

## 9. Rules That Affect How We Build

- **New or significantly updated.** Projects must be newly created after 31 Aug 2026 or significantly updated after that date, with the updates described and demoed.
- **No prior Amazon support.** A project must not have been developed with financial or preferential support from Amazon or Devpost (funded, contracted, or commercially licensed) before the end of the submission period.
- **Third-party integrations.** You must be authorized to use every SDK, API, dataset, or media you integrate, per its terms.
- **Testing access.** Judges must be able to test via the repo and video. Anything behind a login needs credentials in the testing instructions. Keep hosted demos alive through 20 Nov 2026.
- **IP.** You keep ownership. Amazon and Devpost get a non-exclusive license to review and to promote the submission, including your name, likeness, and voice, for three years. You warrant originality and non-infringement.
- **Modifications after the deadline** are only allowed to remove IP-infringing content, personal information, or inappropriate content, and the project must remain substantively the same.
- **Language.** English, or provide an English translation.
- **Disputes.** New York law, binding arbitration (AAA), no class actions.
- **Devpost Terms of Service** apply.

## 13. Signals About What Amazon Wants to See

- **Depth over breadth in the required tech.** Criterion 1 and the "imported and actually called" rule both punish thin wrappers. Use the track APIs deeply (webhooks + media + history for Ring; tools + resources + elicitation + structured output for MCP; focus/D-pad/voice/media for Fire TV).
- **A complete product, not a demo endpoint.** Criterion 2 explicitly asks for a "complete, coherent product experience" and "intuitive interaction model."
- **Realistic distribution.** Criterion 3 cites the Fire TV Appstore and Ring Appstore. Ring's own developer landing page lists elder care monitoring, pet wellness, business intelligence/operations, and home analytics as target categories; Ring's Appstore strategy names elder care, workforce analytics, rental management, and business operations.
- **Priority categories are hints, not constraints.** Ring: access control, business systems, IoT home automation, accessibility, caretaking. Fire TV: AI-enhanced viewing, sports, fitness, family entertainment, multi-modal UX, computer vision. Bee: education, developer experience, personal productivity.
- **Friction logs are worth 10%.** Amazon wants raw developer-experience feedback routed to engineering. Keep a running log from day one.
- **AWS layering is encouraged.** The AWS Builder mini challenge and the $150 credits are designed to get Bedrock/AgentCore/Strands/Kiro into projects.
- **Open source is encouraged.** The Open Source mini challenge rewards public repos with proper licensing and real contributions.
- **Amazon's agent narrative.** Judges Kourtney Meiss and Anisha Malde speak publicly about agent orchestration; Alexa+ is described as powered by MCP; Ring and Fire TV both ship MCP servers for coding assistants. Projects that speak the "agents + MCP" language fit the narrative.
